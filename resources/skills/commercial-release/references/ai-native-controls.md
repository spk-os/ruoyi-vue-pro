# AI-Native 质量与安全控制

## 分工

- Agent：检索、分析、生成候选、执行授权工具、组装证据和提出建议。
- 确定性系统：Schema、编译、测试、策略、哈希、SBOM、查询与发布控制器。
- Independent Verifier：上下文隔离后独立复算、反例检查和证据审计。
- 人类责任人：需求/风险取舍及 DCP、CCB、TR、GA、LDCP、客户授权等不可委托决定。

## 必须加强

- 事实新鲜度：外部事实记录 `observedAt/retrievedAt/source/version`，过期即重采。
- 供应链：记录依赖锁文件、许可证、SBOM、漏洞库版本、构建来源和制品签名。
- 安全隐私：最小权限、秘密引用、PII 分级/脱敏、Prompt 注入隔离、工具参数白名单。
- 可靠性：幂等键、有限重试、熔断、可恢复检查点、回滚验证和失败证据。
- 模型治理：模型/Prompt/Skill 版本、token/时延/成本、置信度、fallback 原因和人工升级。
- 质量：黄金样例、边界/反例、变形测试、差分验证；高风险结论禁止单模型单次采样。

## 传统机制的 AI-Native 替换

例会状态收集改为事件驱动台账和按异常召集；手工文档汇编改为 manifest 自动组装；人工抄录测试结果改为 CI 原始回执；串行角色交接改为带哈希的异步契约；周期性全量审批改为风险分级，但法定/商业/安全门不得删除。
