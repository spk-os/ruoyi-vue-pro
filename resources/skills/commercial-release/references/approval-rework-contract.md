# 审批与自动返工契约

本契约适用于商业发布流程中的 DCP、TR、GA、LDCP 和项目定义的人审门。审批人与 Agent 的职责必须隔离：流程负责执行与返工，审批人只负责基于证据作出决定。

## 正常送审

1. IPD 流程自动启动 Omnigent，并由 Omnigent 自动启动 Claude Code 执行已绑定的阶段或 Activity Skill；禁止要求审批人手工创建、续跑或监控 Agent 会话。
2. Agent 完成产物、证据、追溯、自检及要求的独立验证后，流程才可创建待审批任务。
3. 审批人只查看冻结的基线、原始证据、验证回执、开放风险和前次返工记录，然后选择 `APPROVE` 或 `REJECT`。Agent 不得自批、代批或修改审批决定。
4. `APPROVE` 形成不可变 HumanApprovalRecord，并允许流程进入下一个已授权节点。

## REJECT 自动返工

1. REJECT 必须包含明确、可验证的原因；空原因是无效请求，流程保持待审批。
2. 系统以同一 processInstanceId 保留原决定、产物和证据，追加 reworkCount、rejectedGate、reworkTarget、reworkReason 与 decisionId，禁止覆盖历史或结束流程实例。
3. 流程自动回到当前阶段入口或项目配置的最小受影响节点，自动重新启动 Omnigent→Claude Code 执行；审批人不得人工接管 Agent 执行。
4. 新一轮 Prompt 必须注入审批原因、前次决定 ID、受影响基线和可验证的完成条件。Agent 只能修复并重新生成产物与证据，不能把拒绝改写为批准。
5. 返工产物必须获得新的 runId、哈希并重新验证；要求独立验证的节点必须产生新验证回执且只有 `PASS` 才能再次送审。
6. 完成返工后，流程自动创建新的审批任务；原审批任务与原决定保持可审计。只有审批人再次决定，流程才能继续。

## 失败关闭与上限

- 商用模式禁止 fast/skip/mock/fallback 完成；Skill、Omnigent 适配器、Agent、模型、原始证据或独立验证器缺失时进入 `BLOCKED/FAILED`，不得送审。
- 自动重试与自动返工必须有上限并保持幂等。达到上限后进入人工异常处置，但人工处置只能修复流程配置或外部阻塞，不能直接把失败产物标记为通过。
- 跨阶段影响应按依赖图扩大返工范围；无法证明最小影响子图时，从当前阶段入口重跑。

## 审计验收

一条合格的拒绝—返工—再送审链至少能证明：同一流程实例、两个不同审批任务、原 REJECT 记录、非空原因、自动路由目标、自动 Agent 运行回执、新产物哈希、新独立验证回执，以及新的待审批状态。
